## 1. Project Overview

A full-stack e-commerce platform built for Indian retail stores. The system ships with a customer-facing storefront and a fully-featured backstore administration panel. It is architected as a decoupled SPA — a Laravel 12 JSON API consumed by a Vue 3 single-page application.

**Repository layout:**

```
store/
├── backend/      # Laravel 12 API
└── frontend/     # Vue 3 SPA (Vite)
```

## 5. Backend Deployment

```bash
cd backend

# 1. Install production dependencies (no dev)
composer install --no-dev --optimize-autoloader

# 2. Set environment
cp .env.example .env      # then fill in all values
php artisan key:generate

# 3. Run all migrations
php artisan migrate --force

# 4. Seed reference data (store settings, categories, shipping, roles)
php artisan db:seed

# 5. Create your admin user (see Section 8)

# 6. Cache config, routes, views for production performance
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan event:cache

# 7. Set correct file permissions (Linux/macOS)
chmod -R 775 storage bootstrap/cache
chown -R www-data:www-data storage bootstrap/cache
```

> **Queue worker** (if `QUEUE_CONNECTION=database` or `redis`):  
> Run `php artisan queue:work --daemon` via Supervisor or systemd so notification emails/SMS are processed.

## 6. Frontend Deployment

```bash
cd frontend

# 1. Install dependencies
npm ci

# 2. Type-check (optional but recommended)
npm run type-check

# 3. Build for production (outputs to frontend/dist/)
npm run build
```

Serve the `frontend/dist/` directory as a static site behind Apache (see Section 9). Because the app uses Vue Router in `history` mode, every route must fall back to `index.html`.

## 7. Database Setup

### 7.1 Create the database

```sql
CREATE DATABASE ecommerce CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'ecom_user'@'localhost' IDENTIFIED BY 'strong_password';
GRANT ALL PRIVILEGES ON ecommerce.* TO 'ecom_user'@'localhost';
FLUSH PRIVILEGES;
```

### 7.2 Run migrations

```bash
php artisan migrate --force
```

### 7.3 Seed reference data

```bash
php artisan db:seed
```

This populates:
- **Store settings** — two store records (one active); edit `StoreSettingsSeeder.php` to match your store name and layout before seeding.
- **Categories** — default category tree
- **Brands** — common brand entries
- **Shipping** — shipping providers, zones, and methods
- **Roles** — `Admin`, `Vendor`, `Customer` (required for auth to work)

> Re-run seeds safely: all seeders truncate their tables before inserting, so they are idempotent.

## 8. Creating the First Admin User

There is no web-based admin registration. Create the admin account via Tinker:

```bash
cd backend
php artisan tinker
```

```php
$user = \App\Models\User::create([
    'name'     => 'Your Name',
    'email'    => 'admin@yourdomain.com',
    'password' => bcrypt('strong_password_here'),
]);
$user->assignRole('Admin');
```

Then log in at `https://yourdomain.com/backstore/login`.

### 9.1 Apache VirtualHost — API backend

Save as `/etc/apache2/sites-available/ecom-api.conf`:

```apache
# Redirect HTTP → HTTPS
<VirtualHost *:80>
    ServerName api.yourdomain.com
    Redirect permanent / https://api.yourdomain.com/
</VirtualHost>

<VirtualHost *:443>
    ServerName api.yourdomain.com
    DocumentRoot /var/www/store/backend/public

    # SSL — Certbot will populate these automatically
    SSLEngine on
    SSLCertificateFile    /etc/letsencrypt/live/api.yourdomain.com/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/api.yourdomain.com/privkey.pem

    # Security headers
    Header always set X-Frame-Options "SAMEORIGIN"
    Header always set X-Content-Type-Options "nosniff"
    Header always set Referrer-Policy "strict-origin-when-cross-origin"

    # Allow Laravel's .htaccess to handle URL rewriting
    <Directory /var/www/store/backend/public>
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    # Block access to hidden files (e.g. .env)
    <FilesMatch "^\.">
        Require all denied
    </FilesMatch>

    # Increase upload limit for product images
    LimitRequestBody 20971520

    ErrorLog  ${APACHE_LOG_DIR}/ecom-api-error.log
    CustomLog ${APACHE_LOG_DIR}/ecom-api-access.log combined
</VirtualHost>
```

> Laravel ships with a `public/.htaccess` that handles `mod_rewrite` routing. The `AllowOverride All` directive above is what makes it work.

### 9.2 Apache VirtualHost — Vue SPA frontend

Save as `/etc/apache2/sites-available/ecom-frontend.conf`:

```apache
# Redirect HTTP → HTTPS
<VirtualHost *:80>
    ServerName  yourdomain.com
    ServerAlias www.yourdomain.com
    Redirect permanent / https://yourdomain.com/
</VirtualHost>

<VirtualHost *:443>
    ServerName  yourdomain.com
    ServerAlias www.yourdomain.com
    DocumentRoot /var/www/store/frontend/dist

    # SSL — Certbot will populate these automatically
    SSLEngine on
    SSLCertificateFile    /etc/letsencrypt/live/yourdomain.com/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/yourdomain.com/privkey.pem

    <Directory /var/www/store/frontend/dist>
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted

        # Vue Router history mode — fall back to index.html for all routes
        FallbackResource /index.html
    </Directory>

    # Cache hashed JS/CSS/image assets for 1 year
    <FilesMatch "\.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$">
        Header set Cache-Control "public, max-age=31536000, immutable"
    </FilesMatch>

    # Do not cache index.html itself
    <FilesMatch "^index\.html$">
        Header set Cache-Control "no-cache, no-store, must-revalidate"
    </FilesMatch>

    ErrorLog  ${APACHE_LOG_DIR}/ecom-frontend-error.log
    CustomLog ${APACHE_LOG_DIR}/ecom-frontend-access.log combined
</VirtualHost>
```

> `FallbackResource /index.html` is the Apache equivalent of Nginx's `try_files $uri /index.html` — it tells Apache to serve `index.html` for any URL that doesn't match a real file, which is required for Vue Router's history mode.

## 10. Third-Party Service Setup

### 10.1 Razorpay

1. Create an account at [razorpay.com](https://razorpay.com).
2. Get your **Live API Keys** from Dashboard → Settings → API Keys.
3. Set `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, and `RAZORPAY_WEBHOOK_SECRET` in `.env`.
4. Register the webhook URL (see Section 9.3).
5. Set the Razorpay **Key ID** as `VITE_RAZORPAY_KEY_ID` in `frontend/.env.production` and rebuild the frontend.

### 10.2 Email (SMTP)

Any SMTP provider works. Recommended options for India:

| Provider | Notes |
|---|---|
| **Mailgun** | Generous free tier, reliable deliverability |
| **Amazon SES** | Cheapest at scale |
| **Gmail SMTP** | Free but limited (500/day), use App Passwords |
| **Brevo (Sendinblue)** | 300 free emails/day |

Set `MAIL_MAILER=smtp` and fill in the SMTP credentials in `.env`.

### 10.3 Twilio SMS & WhatsApp (optional)

3. For WhatsApp: apply for a WhatsApp sender or use the **Twilio Sandbox** for testing (`whatsapp:+14155238886`).

## 12. Known Limitations

The following features are designed and partially scaffolded but **not yet implemented** in this release:

- **Payment Gateway Config UI** — Razorpay keys are set via `.env`; there is no admin page to rotate them without server access.
- **User & Team Management** — Spatie roles (`Admin`, `Vendor`, `Customer`) exist in the database but there is no admin UI to create/edit/delete users or assign roles.
- **Marketing & Campaigns** — Coupons are supported; scheduled campaigns, email blasts, and loyalty programs are not.
- **Bulk Product Import/Export** — Products must be created individually via the admin UI.
- **SEO Management** — No meta-tag or sitemap management UI.
- **Queue Workers** — Notifications are synchronous. Under production load, configure `QUEUE_CONNECTION=redis` and run `php artisan queue:work` via Supervisor for async delivery.
- **File storage** — Product images use local disk storage. For production with multiple servers, configure `FILESYSTEM_DISK=s3` and set AWS credentials.
- **WhatsApp Production Sender** — WhatsApp notifications default to the Twilio Sandbox number. Register an approved WhatsApp Business sender before going live.
